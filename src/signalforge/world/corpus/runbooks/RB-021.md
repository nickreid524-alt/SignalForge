Identity signs access tokens with a key identified by `kid`. Validators (the edge gateway) fetch identity's JWKS and cache it.

## Correct order
1. Publish the new key in the JWKS without signing with it.
2. Wait longer than the longest validator cache TTL (edge-gateway `jwks.cache_ttl_seconds`, currently 24 hours), or flush validator caches explicitly.
3. Switch signing to the new `kid`.
4. Retire the old key after all tokens signed with it have expired.

## Failure mode
Signing with a new `kid` before validators have refreshed produces `token rejected: unknown kid` at the gateway for a fraction of requests that grows as new tokens are issued. Identity itself looks healthy because issuance succeeds.

## Recovery
- Flush the gateway JWKS cache (or lower the TTL and wait), or temporarily switch signing back to the previous key.
