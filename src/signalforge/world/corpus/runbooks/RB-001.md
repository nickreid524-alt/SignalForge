Checkout is an orchestration service: almost all of its latency is spent waiting on cart, inventory, pricing, payments and orders. Treat a checkout latency alert as a routing question first.

## Symptoms
- `checkout-p95-slo` alert firing; p95 above 400 ms for five minutes.
- Order completion rate falling while request rate is flat.

## Diagnosis
1. Query `dependency_latency_p95` on checkout for each downstream dependency (cart, inventory, pricing, payments, orders, identity) over the last two hours and compare with the same window yesterday.
2. If one dependency dominates, move the investigation to that service: its own p95, its recent deployments and configuration changes.
3. If no dependency is slow but checkout is, look at checkout itself: recent deployments, call fan-out per order in the logs (`inventory.reserve` and `pricing.quote` call counts), and CPU saturation.
4. Confirm the onset time against the deployment and configuration timeline. A change that lands after the onset cannot be the cause.

## Remediation
- Dependency slow: follow that service's runbook.
- Checkout regression after a release: see RB-004 (rolling back a checkout release).
