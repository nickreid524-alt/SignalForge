The session cache holds sessions and carts. It is sized so that eviction never happens under normal load; any eviction is an incident.

## Symptoms
- `cache_evictions` above zero; `cache_hit_ratio` falling.
- Cart and identity latency rising as they rebuild state from origin services.
- Customers reporting empty carts.

## Diagnosis
1. Query `cache_evictions` and `cache_hit_ratio` on session-cache. Evictions starting at a precise minute point to a configuration change.
2. Check configuration changes on session-cache for `maxmemory` or `maxmemory-policy`.
3. Check `memory_usage` on session-cache; if it is pinned exactly at the new limit, the limit is the cause.
4. Cart deployments that only change logging cannot cause evictions on the cache.

## Remediation
- Restore the previous `maxmemory`. Carts rebuild automatically as customers return.
