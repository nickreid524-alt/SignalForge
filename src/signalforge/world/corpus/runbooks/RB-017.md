Catalog and search-index are the first services to saturate under abusive traffic because product and search pages are unauthenticated.

## Symptoms
- `request_rate` several times normal with no campaign; `catalog-autoscaler-at-max` alert.
- Logs summarising a single user-agent or network range as most of the traffic.
- search-index CPU pinned; catalog 5xx from search timeouts.

## Diagnosis
1. Query `request_rate` on catalog and confirm the step change.
2. Read catalog WARN logs for user-agent and source summaries.
3. Confirm no catalog deployment or configuration change coincides with the onset; a completed maintenance window earlier in the day is not a cause if latency was normal afterwards.

## Remediation
- Block the user-agent or range at the edge gateway; add a cache rule for anonymous search.
