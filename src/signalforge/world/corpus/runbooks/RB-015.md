The gateway rate-limits per key. The key is configurable: `user_id` (default) or `client_ip`. Mobile carriers place thousands of users behind a few NAT addresses, so per-IP limiting punishes mobile users as a group.

## Symptoms
- `gateway-429-ratio` alert; support tickets from mobile users; web unaffected.
- WARN logs `rate limit exceeded key=ip:...` with a large `distinct_users_behind_key`.

## Diagnosis
1. Query `error_rate` with `client=mobile` and `client=web` separately.
2. Check configuration changes on edge-gateway for `ratelimit.key` or `ratelimit.limit`.
3. Verify `request_rate` is flat. A rate-limit incident with flat traffic is a configuration problem, not an attack.

## Remediation
- Restore `ratelimit.key=user_id`; use IP limits only for unauthenticated routes.
