Checkout releases are rolled back with the deploy tool by redeploying the previous version. Rollbacks are safe: checkout owns no schema.

## When to roll back
- A latency or error regression whose onset matches a checkout deployment within a few minutes.
- Change notes mention behaviour that could explain the symptom (fan-out changes, retry changes, feature defaults).

## Procedure
1. Identify the previous good version from the deployment history.
2. Announce in the incident channel; note the deployment ID being reverted.
3. Redeploy the previous version. The deploy tool records the new deployment with `rollback_of` set to the reverted deployment ID.
4. Watch `latency_p95` and `error_rate` for ten minutes.

## After the rollback
- File a post-incident review. Include the deployment ID, the change note that explains the regression and the metric evidence.
