StackDNS is the cluster resolver. Services resolve short names through configured search domains; removing a search domain makes every short name under it fail with NXDOMAIN.

## Symptoms
- Service logs containing `no such host` or `NXDOMAIN` for a name that used to resolve.
- The external dependency behind that name looks down from inside the cluster while its public status is fine or unrelated.

## Diagnosis
1. Query dns node `error_rate` and logs for `NXDOMAIN` entries naming the failing host.
2. Check configuration changes on the dns node for `resolver.search_domains` around the onset.
3. Compare the external dependency's status feed region with our region before blaming the vendor.

## Remediation
- Restore the removed search domain or switch the service to the fully qualified name.
