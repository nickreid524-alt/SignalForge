Logins flow through the edge gateway, which validates tokens issued by identity against identity's JWKS document. Failures can originate on either side.

## Symptoms
- `login-failure-rate` alert on edge-gateway; users see 401 after a successful password entry.
- Identity itself reports healthy.

## Diagnosis
1. Read edge-gateway WARN logs for the rejection reason: `unknown kid` means the gateway does not know the signing key; `expired` means clock or lifetime; `invalid signature` means the wrong key.
2. Check identity deployments for signing-key changes and identity logs for the `kid` being issued.
3. Check edge-gateway configuration for `jwks.cache_ttl_seconds`. A long TTL means the gateway keeps validating with stale keys for hours after a rotation.
4. Replication-lag alerts on identity-db affect reads of account data, not token validation.

## Remediation
- Flush the gateway JWKS cache, or temporarily sign with the previous key. See RB-021 for the correct rotation order.
