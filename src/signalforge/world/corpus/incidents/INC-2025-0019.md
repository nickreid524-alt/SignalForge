## Summary
Catalog pods were OOM-killed about once an hour for four hours, causing brief error bursts on product pages.

## Timeline
- 2025-05-20 16:00 catalog v2025.05.20-1 deployed with the client upgrade.
- 2025-05-21 07:30 `catalog-pod-restarts` fired after the third restart.
- 09:00 heap dump showed retained response buffers.
- 11:15 rollback complete.

## Root cause
The upgraded search client kept a reference to every response body in a diagnostics ring buffer with no size limit.

## Contributing factors
- The leak shipped fifteen hours before the first alert, so the recent-deployments view of the on-call showed nothing.

## Remediation
- Rolled back; pinned the client version; added memory-growth alerting.

## Lessons
- Widen the deployment window when a sawtooth in memory is present.
